## Model selection (validation only)

k grid fixed before the run: 5, 10, 20, 50, 100, 150, 200 (randomized SVD, 220 components).
Validation RMSE rises monotonically with k (0.6934 at k = 5 → 0.6972 at k = 200), so **k = 5 was
selected at the lower edge of the grid**; smaller ranks were not evaluated and the grid was not
changed after the test evaluation. SGD-MF was disabled (as for MovieLens 1M).

## Interpretation (do not over-read)

* SVD improves on the user + item bias baseline by only 0.0056 RMSE; the latent factors add very
  little over the biases on this data.
* For top-10 recommendation a most-popular list is far better offline (NDCG@10 0.0568 vs 0.0039),
  the same pattern as on MovieLens (0.147 vs 0.011). The model's strength is rating prediction.
* Ratings come from tweets generated by the IMDb apps' rating widget between 2013 and 2021, with
  a median of 8/10; they are not a sample of any streaming service's users or catalogue.

## Differences from the MovieLens experiment

| | MovieLens latest-small | MovieTweetings |
|---|---|---|
| Rating scale | 0.5–5.0 (half stars) | 1–10, divided by 2 |
| Filtering | none (source guarantees ≥ 20 ratings per user) | 20-core on users and movies |
| Size after preparation | 100,836 ratings, 610 users, 9,724 movies | 593,204 ratings, 8,574 users, 4,778 movies |
| Selected k | 20 | 5 (grid edge) |
| SVD solver | full | randomized (220 components) |
| SGD-MF | included | disabled |
| Test RMSE (SVD / best bias baseline) | 0.8853 / 0.8943 | 0.6930 / 0.6986 |
| Test NDCG@10 (SVD / most popular) | 0.011 / 0.147 | 0.0039 / 0.0568 |

Errors are not comparable across datasets (different users, rating behaviour and density).

## Operational checks with this model (evidence in `docs/evidence/movietweetings/`)

* API (local uvicorn on the separate registry): known user → `svd` recommendations with titles;
  unknown user → popularity fallback; `/predict` 4.023 for a known pair; user 0, malformed body and
  rating 9.0 → 422; valid feedback → 202 (`03_api_monitoring_session.log`).
* Monitoring: 300 requests from known users → input drift `ok` (PSI 0.0556), cold start 0.66 %;
  300 more from unknown users → input drift `alert` (PSI 4.625), cold start 50 %.
* Retraining on a **copy** of the registry (`02_retraining_gate_rollback_registry_copy.log`):
  dry run passed the gate and changed nothing; rollback restored the previous version; the
  delivered registry was unchanged.
* **Finding:** a candidate trained on 3,000 *random-noise* ratings was **promoted**: it tied the
  approved model on validation (0.71408 vs 0.71412 RMSE) and the configured
  `min_rmse_improvement` is 0.0. On MovieLens the same scenario was rejected. The gate thresholds
  are a client policy decision; a positive minimum improvement and/or a human approval step before
  promotion is recommended for production (see `RETRAINING.md`).
